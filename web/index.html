01

THE CENTRAL THESIS

Do not render the universe. Evolve it.

Traditional game engines usually make the scene, object hierarchy, or level file the center of reality. Latticeborn reverses that assumption. The canonical world exists independently from any visual client. Renderers receive filtered projections of state; they do not own truth.

Identity without weight

An entity is a durable identifier. Components, graph edges, and field participation give it meaning.

Objects above, streams below

Humans author objects and behaviors. The machine executes dense transformations over contiguous data.

Time is structural

Every change is ordered, attributable, replayable, branchable, and inspectable.

Resolution is fluid

The same world may be represented statistically, agentically, physically, or visually at once.

04

SIMULATION RUNTIME

The engine schedules transformations, not object chatter.

Every system declares what it reads, writes, where it operates, how often it runs, and which execution backend it can use.

SYSTEM(Gravity) {
  .reads   = { Position, Mass },
  .writes  = { Force },
  .domain  = SPATIAL,
  .rate_hz = 60,
  .backend = CPU_SIMD | GPU_COMPUTE,
  .mode    = DETERMINISTIC
};
Input→Intent→Navigation→Forces→Physics→Consequences→Commit

Scheduler contract

  • Build a dependency DAG from declared read/write hazards.
  • Batch entities by archetype, spatial cell, and execution affinity.
  • Run independent systems concurrently.
  • Fuse compatible passes to reduce memory traffic.
  • Route stable hot kernels to SIMD, GPU compute, FPGA, or ASIC implementations.
  • Preserve a deterministic mode for rollback, replay, tests, and consensus.

PHYSICS & FIELDS

No single solver deserves sovereignty.

A reality engine must choose mathematics by regime rather than force all phenomena into one abstraction.

Rigid bodies

Broad phase, narrow phase, constraints, sleeping, continuous collision detection.

Reference integration: Jolt Physics

Fluids

SPH for local interaction, grid solvers for bounded fidelity, shallow-water models for regional flow.

Soft matter

Position-based and extended position-based dynamics for cloth, ropes, tissue, and deformables.

Destruction

Fracture graphs, sparse voxels, SDFs, structural constraints, and procedural remeshing.

Climate

Multi-scale advection, diffusion, radiation, hydrology, and statistical downscaling.

Biology

Metabolic fields, ecological networks, morphogenesis, populations, and agent-level organisms.

09

NETWORKING & DISTRIBUTION

Move meaning, not pixels.

Control and durable events

NATS Core carries ephemeral command, request/reply, service discovery, and low-latency state signals. JetStream carries durable work, consequential events, and replayable streams.

Dense real-time replication

QUIC or engine-native datagrams carry snapshots, compressed component deltas, prediction corrections, and asset references. Shared memory is used within a host.

Hard boundary

NATS is not a draw-call bus. Vertices, textures, framebuffers, and per-frame GPU command streams stay local to the renderer.

Interest management

A client subscribes to a changing semantic and spatial horizon: nearby entities, visible cells, audible events, owned assets, mission state, social context, and predicted future relevance.

  1. P0Immediate player state, collisions, ownership, authority.
  2. P1Nearby dynamic entities and combat-critical events.
  3. P2Animation, sound, particles, and secondary motion.
  4. P3Distant or slowly changing objects.
  5. P4Cosmetic, procedural, or reconstructible detail.
10

PERSISTENCE

Memory is hot. History is durable. Meaning is queryable.

Hot world state

In-memory ECS tables, spatial indices, field tiles, and solver buffers.

Relational truth

PostgreSQL for identities, permissions, ownership, transactions, inventories, and configuration.

Semantic graph

Apache AGE or a replaceable graph layer for relationships, provenance, plans, and world knowledge.

Immutable history

Append-only event segments and checkpoints in content-addressed object storage.

The database must not participate in every physics tick. Simulation commits checkpoints and significant events asynchronously, while authoritative tick state remains memory-resident.

RENDERING

One world. Many senses.

Each renderer maintains a local projection ECS. It resolves assets, reconstructs procedural detail, interpolates snapshots, predicts motion, and builds a render graph appropriate to its hardware and aesthetic.

High-fidelity desktop and XR

Atom render pipelines, physically based materials, Vulkan/DirectX/Metal backends, large assets, high-end lighting, and deep native customization.

Lightweight and expressive

Fast iteration, approachable scene authoring, compact deployments, stylized rendering, mobile targets, and direct RenderingServer access where needed.

Ubiquitous access

WebAssembly simulation projections, WebGPU rendering, glTF assets, browser-native collaboration, and progressive fidelity.

Worlds without pixels

An agent can “render” the same universe as entities, affordances, relationships, beliefs, hazards, causal history, and possible actions.

Typical visual pipeline

ProjectionCullingLODAnimationGeometryLightingTransparencyVolumetricsPostUI

Rasterization remains the primary real-time path. Ray tracing augments shadows, reflections, global illumination, or complete path-traced modes. Procedural geometry may be generated on the server, CPU client, or GPU depending on whether it changes truth or only appearance.

AGENTS & SCRIPTING

Behavior is capability-secured computation.

World laws, user scripts, mods, and agent skills run as sandboxed WebAssembly components. The runtime grants explicit, revocable capabilities rather than ambient authority.

capabilities {
  read:  nearby.transforms, local.weather, self.inventory
  write: self.intent, self.memory
  emit:  speech, movement_request, trade_offer
  deny:  filesystem, raw_network, arbitrary_database
  budget: { cpu_ms: 2, memory_mb: 32, events: 64 }
}

Deterministic law

Versioned rules participate directly in authoritative simulation.

Bounded agency

Agents perceive filtered worlds and act through validated intents.

Hot evolution

Components can be upgraded, rolled back, tested, and migrated independently.

SECURITY, TRUST & GOVERNANCE

Authority is explicit, local, and auditable.

  • Capability-based access for scripts, services, agents, and administrators.
  • Signed commands and provenance-aware events for high-value transitions.
  • Server authority over canonical outcomes; clients submit intents.
  • Schema validation, resource metering, rate limits, and deterministic validation.
  • Namespace isolation for universes, tenants, mods, and experimental branches.
  • Reproducible builds, software bills of materials, and signed release artifacts.
  • Privacy boundaries separating public world facts from private agent memory.

MACHINE SYMPATHY

Optimize data motion before arithmetic.

Most performance failures are not failures to compute. They are failures to place, batch, predict, or reuse data.

Memory locality

Contiguous tables, hot/cold splitting, compact component schemas, arenas, and cache-aware tiling.

Batching

Transform many similar values per pass; avoid virtual dispatch and pointer-chasing in hot loops.

Specialization

Profile stable high-load kernels, then graduate them from scalar CPU to SIMD, GPU, FPGA, or ASIC.

Approximation

Spend fidelity only where error becomes perceptible or causally important.

60 Hzinteractive authoritative target
10⁵locally visible lightweight entities
10⁶+active entities per regional shard
billionsdurable semantic identities, partitioned

These are design targets, not promises. Actual capacity depends on component density, solver complexity, update frequency, hardware, and consistency requirements.

REFERENCE IMPLEMENTATION

The spine exists. Go run it.

Phase 0 and Phase 1 of the roadmap are implemented in this repository as a dependency-free reference core: a schema registry and component ABI, archetype ECS over typed-array columns, a hazard-derived scheduler, a sealed event log, continuous fields, a semantic graph, capability-sandboxed laws, procedural genesis, and a projection layer with interest management and priority tiers.

Terminal client

Proofs, not claims

latticeborn verify demonstrates determinism, replay, rollback, branching, log integrity, and sandbox containment.

node bin/latticeborn.js verify
node bin/latticeborn.js demo
npm run serve             # publication + live world at localhost:8080
Scope

This is the spine, not the skin. The reference core is JavaScript so it can run unmodified in a terminal and a browser. The C17 ABI, Rust services, Jolt integration, NATS fabric, and the O3DE, Godot, and WebGPU clients described above remain Phase 2 and beyond.

THE LATTICEBORN MANIFESTO

Reality is state in motion.

We will not confuse a scene graph for a world, a frame for a moment, or a renderer for reality. We will model identity separately from representation, meaning separately from storage, and law separately from appearance. We will let objects emerge over fields, let history remain executable, and let every observer receive the world it can perceive. We will optimize movement of data before multiplication of instructions. We will specialize what is stable, approximate what is distant, and preserve what is causally important. The engine will not own the universe. It will serve it.
